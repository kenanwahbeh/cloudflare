# لوحة Cloudflare — واجهة مبسّطة لـ DNS والأنفاق

واجهة عربية (RTL) بتشتغل كـ Cloudflare Worker، بتخليك تدير سجلات الـ DNS وأنفاق Cloudflare Tunnel
بدون ما تدوخ بلوحة كلاودفلير الرسمية.

## شو بتعمل

**تبويب سجلات DNS**
- كل النطاقات بحسابك بقائمة منسدلة وحدة (بتتذكّر آخر نطاق اخترته)
- جدول واضح: بحث فوري، فلترة حسب النوع، وإضافة/تعديل/حذف
- تبديل البروكسي (السحابة البرتقالية) بضغطة وحدة من الجدول
- بيميّز السجلات المربوطة بأنفاق بشارة «نفق»
- بيمنعك من الغلط: TTL بينضبط تلقائياً لما البروكسي مفعّل، وحقول الأولوية بتظهر بس لـ MX و SRV

**تبويب الأنفاق**
- قائمة أنفاقك مع حالتها (شغّال / متذبذب / مفصول) وعدد الاتصالات
- **إضافة نطاق للنفق بخطوة وحدة** — هي أهم ميزة. عادةً لازم تعمل خطوتين منفصلتين:
  تعديل قواعد الـ ingress، وبعدين تنشئ سجل CNAME مُمرّر عبر البروكسي يأشر على
  `<معرّف-النفق>.cfargotunnel.com`. هون بتكتب الاسم والخدمة وبس — الواجهة بتعمل الاثنين سوا.
- تعديل وحذف النطاقات (الحذف بيشيل قاعدة الـ ingress وسجل الـ CNAME التابع للنفق معاً)
- إنشاء نفق جديد وإظهار أمر التثبيت الجاهز لـ `cloudflared`

## المتطلبات

- Node.js 18 أو أحدث
- توكن Cloudflare API (مو Global API Key) بالصلاحيات التالية:

| النطاق | الصلاحية | ليش |
| --- | --- | --- |
| Account | `Cloudflare Tunnel` → **Edit** | قراءة وإنشاء وتعديل الأنفاق وإعداداتها |
| Zone | `DNS` → **Edit** | إضافة وتعديل وحذف سجلات الـ DNS |
| Zone | `Zone` → **Read** | قراءة قائمة النطاقات |

بتعمل التوكن من: **My Profile → API Tokens → Create Token → Custom token**.
تحت `Zone Resources` اختار **All zones** (أو النطاقات اللي بدك تديرها).

## التشغيل

```bash
npm install

# سجّل دخول wrangler لحسابك على كلاودفلير
npx wrangler login

# احفظ الأسرار (ما بتنحفظ بالريبو — بتنخزّن مشفّرة عند كلاودفلير)
npx wrangler secret put CLOUDFLARE_API_TOKEN
npx wrangler secret put UI_PASSWORD

npm run deploy
```

بعد النشر بيطلعلك رابط بالشكل `https://cf-console.<اسم-حسابك>.workers.dev` — افتحه وسجّل دخول
بكلمة السر اللي حطّيتها بـ `UI_PASSWORD`.

### تعديل معرّف الحساب

`CLOUDFLARE_ACCOUNT_ID` موجود بـ `wrangler.toml` تحت `[vars]`. إذا بدّلت الحساب، غيّره من هناك.

### التشغيل المحلي (اختياري)

```bash
cp .dev.vars.example .dev.vars   # وعبّي القيم
npm run dev                       # بيفتح على http://localhost:8787
```

`.dev.vars` مُتجاهَل بـ `.gitignore` وما بينرفع للريبو.

## الأمان

- **التوكن ما بيوصل للمتصفح أبداً.** كل طلبات Cloudflare API بتصير من الـ Worker نفسه؛
  المتصفح بيحكي بس مع `/api/*` تبع اللوحة.
- الواجهة كلها (مو بس الـ API) محمية بكلمة سر. الجلسة كوكي موقّعة بـ HMAC-SHA256،
  `HttpOnly` و `Secure` و `SameSite=Lax`، وصلاحيتها 12 ساعة.
- مقارنة كلمة السر بزمن ثابت، مع كبح بعد 8 محاولات فاشلة.
- تغيير `UI_PASSWORD` بيلغي كل الجلسات القديمة تلقائياً (مفتاح التوقيع مشتق منها).

> **استخدم كلمة سر قوية.** الرابط على `workers.dev` متاح للإنترنت. لحماية إضافية،
> فيك تحط الـ Worker خلف [Cloudflare Access](https://developers.cloudflare.com/cloudflare-one/policies/access/).

## شو بيصير خلف الكواليس

إضافة نطاق لنفق بتعمل:

1. `GET /accounts/{account}/cfd_tunnel/{tunnel}/configurations` — تقرأ الإعداد الحالي
2. تضيف قاعدة `{ hostname, service, path? }` قبل قاعدة الـ catch-all الأخيرة
3. `PUT .../configurations` — تحفظ الإعداد
4. تختار النطاق (zone) الأطول اللي بيغطي الاسم، وتنشئ أو تحدّث سجل
   `CNAME → {tunnel}.cfargotunnel.com` مع `proxied: true`

عند الحذف، سجل الـ DNS بينحذف **فقط** إذا كان من نوع CNAME وبيأشر على هالنفق بالذات —
فما في خطر تحذف سجلاً تاني بالغلط.

## حدود معروفة

- الأنفاق المُدارة محلياً (locally-managed، يعني بملف `config.yml` على السيرفر) ما بتنقرأ
  إعداداتها من الـ API. الأنفاق المنشأة من هون كلها مُدارة من كلاودفلير.
- حذف نفق ما بيحذف سجلات الـ DNS التابعة إله تلقائياً — الواجهة بتنبهك وبتقدر تحذفها من تبويب DNS.
- الواجهة بتغطي DNS والأنفاق بس. باقي إعدادات كلاودفلير (الكاش، الأمان، القواعد) بتضل من اللوحة الرسمية.
